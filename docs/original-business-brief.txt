# SECTION 7 — PAYFAST PAYMENT INTEGRATION

Use Payfast as the confirmed online payment provider.

Support:
- Card payments.
- Instant EFT when activated for the merchant.

Also support:
- Manual EFT.
- Cash on delivery.
- Payment on collection.

### Payfast implementation

Follow current official Payfast developer documentation.

Implement:
- Sandbox mode.
- Live mode controlled through secure configuration.
- Server-generated payment requests.
- Valid payment signatures.
- Unique merchant order references.
- Correct amount handling.
- Verified payment notifications.
- Transaction reconciliation.
- Proper error handling.
- Duplicate notification protection.

### Payment security

Do not:
- Store raw card information.
- Trust client-supplied payment amounts.
- Mark an order as paid because a success page was opened.
- Accept unverified transaction notifications.
- Expose merchant credentials.
- Allow replayed notifications to change accounting incorrectly.

Validate payment notifications using the verification steps required by official Payfast documentation, including signature, source verification, transaction amount and merchant/order identifiers.

Process verified events idempotently.

### Payment process

Customer selects Payfast → Server creates pending order/payment record → Customer enters hosted payment flow → Payfast sends verified notification → Server updates payment record → Order state updates → Notifications are generated.

Handle:
- Successful payment.
- Failed payment.
- Abandoned payment.
- Duplicate notification.
- Delayed notification.
- Incorrect amount.
- Expired payment.
- Refund.
- Payment/order reconciliation.

For Cash on Delivery, Manual EFT and Payment on Collection, show accurate pending payment status until payment is verified or recorded as received.

### Inventory

Create a defined reservation/expiry strategy for pending online payments.

Use database transactions to prevent overselling.

Release reserved stock when payment fails or an unpaid reservation expires.

Do not accidentally release stock for successfully paid orders.

### Refunds

Implement a secure admin-controlled workflow.

A requested refund is not the same as a completed refund.

When an external refund must be performed in the Payfast dashboard or through an available provider capability, record and reconcile that process correctly.

### Live activation

Do not activate live payments before:
- Merchant account approval.
- Production credentials.
- Sandbox testing.
- Production webhook testing.
- Successful payment verification.
- Business-owner approval.
